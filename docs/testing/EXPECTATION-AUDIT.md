## Measurement discipline

The first final-candidate campaign recorded FAIL: 371 discovered tests, three
failures and two skips. All three failures were routing test count assertions
still expecting 57 after adding the dedicated setup case (58 total). The update
keeps the original 57 cases, checks the new case selects only loop, and confirms
a wrong prediction still fails. The grader and accepted predictions were not
relaxed. This failed campaign is retained; the replacement must run under a new
session/input pin rather than overwrite it.

The next campaign passed 14/14 gates with 372 tests (370 pass, two skips). A later
review tightened the export guard to reject case variants/resolved aliases of
.git, so that passing input pin is historical for the pre-hardening snapshot.
The latest source has a separate final hardened campaign and refreshed integration
hash; the earlier reports remain historical.

Final local outcome: Repo 1 passes 14/14 fixed gates (372 tests, 370 pass, two
skips); its Python 3.12 changed-area run has 62 tests (61 pass, one skip). Repo 2
has 73 tests (72 pass, one skip) under each available runtime. The final source
hashes match the refreshed cross-repo fixture record. No new model calls, remote
CI runs, commit or push were performed for these candidates.

Keep successful, failed, skipped, blocked and not-run observations separate.
The injected error messages in runner unit tests are intentional negative controls,
not evidence that the final campaign failed. A command rejected before execution
by automatic approval review is also not an executed failing test. The earlier
review attempt was blocked by usage-limit failure; resumed checks use the same
authorized path after the user's continuation instruction.

The cross-repo record at [WORKFLOW-SETUP.json](WORKFLOW-SETUP.json) is generated by
a deterministic harness with real fixture edits/assertions, zero model calls,
five observations and two completed cycles. Its current helper/instruction hashes
must match the reviewed sources before citing it. Older local runs are retained
separately; do not rewrite historical measured failures as successes.

Final local counts and exact verification input fingerprints are recorded in
[setup validation](WORKFLOW-SETUP.md) and [candidate captures](SETUP-CANDIDATE-CHECKS.json). A passing
helper operation is not a passing business task. Reproducible release archives,
real-user interview trials and production reliability are NOT_RUN in this session.
